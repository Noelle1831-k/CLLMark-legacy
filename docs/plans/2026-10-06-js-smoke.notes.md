## Oracle execution evidence
- MBJSP: `node --check` then `node candidate.js` with NODE_PATH=.benchmark-cache/node/node_modules (lodash 4.17.21). Assembled program = prompt header + full function + MBXP test. Exit code 0 → PASS. Tests print nothing on success.
- Sample of 120: generated 47 PASS / 13 FAIL; human 54 PASS / 6 FAIL. No COMPILE_ERROR, no TIMEOUT.
  - Generated FAILs are real assertion failures (the MBXP test's message references an undefined `x`, so they surface as `ReferenceError: x is not defined` after the comparison fails) plus one stack overflow (MBJSP_550).
  - Human FAILs (MBJSP_104/106/110/129/140/156) are upstream MBJSP canonical-solution defects: the prompt signature uses lowercased parameters (`addLists(testlist, testtup)`) while the canonical body uses camelCase (`testTup`). This is a data property, not a harness bug. It is excluded from paired retention as "originally failing".
- js_projects: each project is copied from the pinned checkout (.benchmark-cache/js-projects/NAME, without node_modules/.git), node_modules is symlinked, and unit files are overwritten. The clean copy is byte-identical to the pinned checkout. Only the watermarked file differs in the marked copy. Tests load the library through relative requires ('..', '../', '../../'), so the watermarked sources are exercised, not node_modules/js-yaml or node_modules/minimist (those are mocha/tape transitive deps).
  - Original and marked both PASS: bytes 30 passing, cookie 47 passing, js-yaml 284 passing + 2 pending, minimist tape 153 pass.

## Harness observations (not fixed; nothing failed)
- benchmarks/utility.py:221 runs project tests with cwd=`cache/project`, so `test-attempt-*.stdout/stderr` land in `cache/project/`. evaluate_utility (utility.py:108) only globs the cache root. The per-unit `.utility/` for js_projects therefore contains only result.json, and project test logs survive only in the shared cache. If the cache were cleared, the failure evidence for projects would be lost, which contradicts RESEARCH_LOOP.md's "清理共享缓存后仍可阅读失败证据". A 1-line harness fix is possible, but it changes the utility.py digest and so the cache keys and protocol.
- Project cache entries hold a full project copy (js-yaml including dist/) per distinct file set. This is fine at 4 projects.
