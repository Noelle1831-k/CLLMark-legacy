## 阶段 C：新增规则与旧规则安全修正（方法改动）

| 字段 | 内容 |
| --- | --- |
| 假设 | 新增 Python 8、C 7、C++ 8 个规则对（比特 0 为常见形式，规则区域互斥），并为旧规则加入只拒绝不安全位置的守卫；容量应上升，功能回退应消失，恢复率与结构性质不下降。 |
| 审计 | `tools/rule_audit.py` 全量语料：新增 Python 规则对幂等/可逆失败 0、语法回退 0、与其他规则对干扰 0；C/C++ 新规则对仅剩个位数版式类可逆失败。 |
| 全量 | `20261005T184009696291Z_e2dc5610_eff2aaf0`，可比，**门禁未通过** |
| 改善 | 功能回退 7 → 0（效用保持 96.53% → 100%），恢复率 99.60%，原始位准确率 98.88%，语法保持 99.99%，幂等 99.97%，可逆 93.90% → 95.79%，互不干扰 96.91% → 97.67%，flip_1 88.08% → 91.98%，容量覆盖 57.49% → 59.64%（mbpp_human 可嵌入 41 → 72）。 |
| 未通过项 | ① 58 个原可嵌入单元失去容量（`declare` 43、`while_to_for` 8、`for_OOO` 6 等），均来自旧规则安全修正，且这些单元没有获得新规则；其中 22 个 MBCPP 单元因此失去配对的功能测试。② mbpp_human 新增可嵌入单元中 2 个偶然匹配码字（MBPP_415、MBPP_850），FPR 0 → 2.78%，超出 1 个百分点容差。 |
| 分析 | `declare` 合并守卫过严：即使两条声明之间没有任何语句，也要求初始值为常量。MBCPP 单元是不含函数签名的函数体片段，依赖函数定义或花括号块的新规则（void_return、array_parameter、else_after_return）在这些片段上基本不适用。 |
| 下一步 | 放宽合并守卫为“只要求被跨越的语句不影响被上移的声明”；为函数体片段补充可用的新规则；重新评估 FPR 门禁在可嵌入集合扩大时的统计意义（新增单元的机会匹配率约 1/16）。 |
