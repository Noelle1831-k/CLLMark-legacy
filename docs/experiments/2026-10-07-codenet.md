## 结论

1. **判题环境可信**：手写标准答案嵌入前通过 2,511/2,513（每个变体相同）。两个例外是数据本身：`p00186.py` 导入 CPython 内部模块 `test.support`；`p02780.cpp` 在 case-6 输出未定义行为的值。生成代码嵌入前通过率：Python 81.9%、C 81.2%、C++ 70.3%、JavaScript 82.1%（C++ 中 123 份使用非标准的 `std::stdin`）。
2. **容量**：生成代码冗长（平均约 300 行），四种语言 G 组 100% 可嵌入；文件粒度容量中位数 15–21，节点粒度 90–194。手写代码文件粒度中位数 6–11，可嵌入率 Python 55%、C 77%、C++ 75%、JavaScript 47%（legacy）；extended 和节点粒度提高到 70–95%。G 与 H 的可嵌入率差在文件/legacy 下为 +23 至 +53 个百分点。
3. **恢复与检测**：所有组嵌入后恢复率 ≥98.8%（文件粒度 C++_H 最低）。未嵌入代码误匹配集中在 C/C++（文件/legacy：C_G 5.3%、C_H 2.5%、C++_H 8.9%），与 BCH(7,4) 单比特纠错下 8/128≈6.25% 的随机匹配率同量级；Python、JavaScript 接近 0。H 组 FPR 2.0–3.7%，这是 4 比特消息加纠错的固有下限，不能作为独立检测结论。
4. **攻击**：flip_2 几乎完全破坏恢复（≤0.9%），符合单比特纠错。flip_1 在 C/C++/JavaScript ≥96%，但 Python_G 只有 48%（文件）/55%（节点）：963 个单元的首个槽位是 `init_list`（2.2），施加其逆规则会同时改变 `list` 槽位的读数，翻转 2 比特（473 例）；另 43 例是嵌入后已有 1 比特误差、攻击再加 1 比特。这是规则间不独立（Python_G 独立性 95.1%）的直接后果。
5. **语法**：tree-sitter 在嵌入前就不能解析 26% 的 C++_H、18% 的 C++_G 和 12% 的 C_H（宏、GNU 扩展），表中“syntax ok”偏低主要来自这部分。嵌入新引入的语法失败：文件粒度 C++_G 16、C++_H 13–18、Python_H 2；节点粒度为 0。
6. **功能保持**：生成代码几乎不回退（C++_G 文件粒度 1 例，C_G 部分用例 2 例），回退集中在手写 C++（55–76 例，保持率 91–93%）和手写 C（8–18 例）。extended 回退更多是因为容量增加后更多手写单元被嵌入，而不是扩展规则本身。
7. **回退的规则归因**（文件粒度两个运行逐条单规则重放，[bisect 脚本](2026-10-07-codenet.bisect.py)，结果 [legacy](2026-10-07-codenet.bisect-file-legacy.json) / [extended](2026-10-07-codenet.bisect-file-extended.json)）：75/75 与 98/98 个回退都能由单条样式复现，没有只在组合时出现的；肇事规则全部是 legacy 规则对，扩展规则对（`assignment_paren`、`literal_order`、`return_paren`、`loop_braces`、`condition_paren`、`trailing_comma`）一例也没有。缺陷类别（例数取文件/extended 运行）：
   - 宏不可见：`main_style` 4.1/4.5 把 `signed main` 改成 `int main`，遇到 `#define int long long` 变成 `long long main`（17+17 例）。
   - 类型不可见的 I/O 改写：`input` 9.4/9.3 把 `cin>>` 改成 `scanf("%d")`，对 `long long`/字符串读错，或与 `sync_with_stdio(false)` 混用导致超时；`output` 9.1/9.2 把 `cout<<` 改成 `printf("%d")`，`long long` 溢出（合计 35 例）。
   - 运算符优先级：`array_access` 5.3 把 `a[i].f` 改成 `*(a + i).f`（14 例，编译失败）。
   - 用户类型缺少运算符：`self_assignment` 2.1 把 `x = x / y` 改成 `x /= y`、`equal_to_not_equal` 2.3 把 `==` 改成 `!(!=)`，类型只重载了 `/`、`==`（17 例）。
   - 副作用重复：`self_assignment` 2.2 把 `*p++ += c` 改成 `*p++ = *p++ + c`；`exp_cmp` 2.9 展开比较。
   - 存储语义：`array_init` 5.1 把栈数组改成 `malloc` 指针，`sizeof` 语义改变（栈溢出检测触发）。
   - Python 记号粘连：`list` 2.3 把 `in[0]` 改成 `inlist([0])`，`f_string` 6.3 把 `or"NO"` 改成 `orf"NO"`。
   - C++ 模板尖括号：`reverse_compare` 2.7 交换比较操作数后破坏了模板实参（生成代码 1 例，编译失败）。

节点粒度（64/65 例）未逐条重放，回退清单与规则共现见报告第 3 节。

## 覆盖缺口与限制

- 不限制内存（数据集的 `memory_limit_mb` 未施加），超时 = 题目时限 × 3，超时重试 1 次。
- 节点粒度回退没有单规则重放；生成代码只有一份（未多次采样），单一 seed 与水印 `1010`，没有置信区间。
- 未嵌入的手写单元（容量 < 7）不参与功能保持与 FPR 统计；Python_H 的 FPR 分母随解包而变化。
- 这里没有修改任何规则。上面的缺陷是 legacy 规则的语义保持问题，修复属于方法改动，需要另立方案并按 AGENTS.md 运行 `make benchmark` 与 `make repo-check`。
