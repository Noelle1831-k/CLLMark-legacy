# 分析—委派—审查流程

主会话负责判断，子代理负责执行。主会话尽量不读原始产物（长日志、完整 diff、整份 report），只读子代理摘要和关键片段。

1. **分析**：只读必要文件。大范围搜索派 Explore 子代理，只取结论。需要数据时，让 implementer 写脚本统计并把结果写入文件，主会话只读结果。
2. **写方案** `docs/plans/<YYYY-MM-DD>-<主题>.md`（修订时在文件内追加"v2"等小节，不另建文件），包含：
   - 目标与范围
   - 根因及证据（文件:行、样本 ID、数字）
   - 逐文件、函数级改动
   - 验收标准：具体测试名、审计数字、门禁项和阈值
   - 禁止事项，以及属于工程改动还是方法协议改动
   要具体到实现者无需再做设计决定。
3. **实现**：派 implementer，只传方案路径和版本号，不在 prompt 里复述方案。互不重叠的子任务可以并行；会改同一文件的必须串行。
4. **实验**：实现和单元测试通过后，派 bench-runner 跑 smoke + 全量 benchmark。一次只跑一个全量 benchmark。
5. **审查**：看 `git diff --stat`、关键 hunk 与两份摘要。不达标就修订方案，用 SendMessage 续用原来的子代理，不新开。
6. **不下放的决定**：协议是否变化、结果是否可比、是否建立新参考或提升基线（基线提升由用户执行）、实验记录结论（docs/experiments/）、向用户汇报。

每轮结束向用户报告：方案版本、run_id、门禁结论、未通过项、下一步。
